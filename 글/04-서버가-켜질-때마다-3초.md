# 서버가 켜질 때마다 3초씩 멈추던 이유

2026-11-16

느린 틱을 단계별로 나눠 재기 시작하고 나서, 재시작할 때마다 이런 줄이 하나씩 찍혔다.

```
[느린 틱] 3571ms · 가장 긴 기능 packet-cache-warmup 242ms · GC 74ms · 단계 플러그인 작업 3537 (서버 시작)
```

서버가 막 켜진 순간이라 아무도 접속하지 못하는 때다. 플레이어가 느낄 일은 없다.
그래도 3.5초 중 3.3초가 어디에 쓰였는지 아무 이름도 없다는 게 마음에 걸렸다. 플러그인 작업이라는데, 우리가 이름표를 붙여 둔 작업 중에는 그렇게 오래 걸린 게 없었다.

## 이름표가 없는 작업 찾기

평소에는 엔진 타이밍을 켜 두지 않는다. 그래서 시험 서버의 설정을 잠깐 바꿔 **켜지는 순간부터** 타이밍을 켜고, 첫 틱이 지난 뒤 보고서를 뽑았다.

```
Task: closure@plugins/EZCore/src/pet/PetIconPack#L113(Single)  Time: 2997ms  Count: 1
```

한 줄이 3초 가운데 3초를 다 갖고 있었다. 펫 아이콘 리소스 팩을 다시 만드는 작업이었다.

## 팩을 두 번 만들고 있었다

EZ는 펫 그림, 메뉴 그림, 글꼴, 모델을 전부 코드로 만들어 리소스 팩 세 개로 묶는다. 그중 아이콘 팩이 10MB쯤 되고, 암호화해서 내보낸다.

서버가 켜질 때 순서는 이렇다.

1. 코어 플러그인이 켜지면서 팩을 만든다
2. 게임 플러그인 9개가 차례로 켜지면서 자기 게임 그림을 팩에 더한다
3. 게임마다 다시 만들면 9번 만들게 되니, 첫 틱에 한 번만 다시 만든다

여기까지는 의도한 대로다. 문제는 이 팩이 내용이 같으면 같은 버전 번호가 나오게 만들어져 있었다는 점이다.
버전이 같으면 휴대폰은 팩을 다시 받지 않는다. 서버도 같은 파일이 이미 있으면 다시 만들 필요가 없다. 그런데 매번 다시 만들고 있었다.

## 한 번 더 속았다

처음엔 "같은 버전 파일이 있으면 다시 쓰기"만 넣었다. 시험 서버를 두 번 켜 보니 서버 시작은 6.5초에서 3.4초로 줄었다. 1번에서 만드는 팩을 다시 쓰게 됐기 때문이다.
그런데 첫 틱은 여전히 2.9초였다.

팩 만들기 안쪽을 단계별로 재 보니 정말로 팩을 다시 압축하고 있었다.

```
모으기 78ms · 팩 2339ms · 목록 0ms
```

같은 파일이 있으면 다시 쓰라고 했는데 다시 만든다는 건, 그 순간 파일이 없었다는 뜻이다.
따라가 보니 1번이 끝날 때 도는 정리 코드가 범인이었다. "지금 쓰지 않는 예전 팩 파일"을 지우는데, 그 시점에는 지난번 3번에서 만든 최종 팩(게임 그림이 다 들어간 것)이 아직 쓰이기 전이다.
그래서 매번 지우고, 몇십 ms 뒤 3번에서 같은 파일을 처음부터 다시 만들고 있었다.

## 고친 것

- 같은 버전 파일이 있으면 그대로 쓴다
- 켜질 때의 첫 빌드에서는 정리하지 않는다. 다시 만들 때(3번) 정리한다
- 팩은 임시 이름으로 다 쓴 뒤에 진짜 이름으로 바꾼다. 쓰다가 서버가 꺼져도 반쯤 쓴 파일을 "같은 버전"으로 착각하지 않게

| | 서버 시작 | 첫 틱 |
|---|---|---|
| 고치기 전 | 6.5초 | 3.0초 |
| 고친 뒤 | 3.3초 | 0.36초 |

팩 파일 이름(버전)은 고치기 전과 똑같다. 휴대폰은 아무것도 다시 받지 않는다.

## 남은 생각

- 사람이 못 느끼는 3초라도 이름 없는 시간은 쫓아갈 만하다. 이번엔 재시작이 3초 빨라졌고, 시작할 때마다 10MB를 압축 · 암호화하던 CPU도 아꼈다
- 캐시를 만들 때는 "언제 지우는지"를 같이 봐야 한다. 이번 버그는 캐시가 아니라 청소부에 있었다
- 처음 고친 뒤 숫자가 반만 좋아졌을 때 거기서 멈추지 않은 게 다행이었다
